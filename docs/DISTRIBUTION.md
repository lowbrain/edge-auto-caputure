## A. 法務・コンプライアンス（最優先）

### D-A1. LICENSE ファイルがない〔**済**〕

リポジトリにも配布フォルダにも `LICENSE` / `NOTICE` の類が**一切ない**（確認済み）。

ライセンス未指定のまま第三者に渡すと、受け取った側は法的には**何の権利も持たない**
（使用・複製・再配布のいずれも許諾されていない）状態になる。
社内配布でも「これ使っていいのか」が宙に浮く。

MIT / Apache-2.0 / 社内限定の独自条項、いずれにせよ**明示が必要**。
これは配布の前提条件。

**現状の対応**: **MIT License** を採用（著作権表示: 2026 lowbrain・個人名義）。
`LICENSE` を追加し、`pyproject.toml` に `license`/分類子、`README.md` にライセンス節を追記済み。
配布時は `build.ps1` が `LICENSE` を `dist\` へ `LICENSE.txt` として同梱する。

### D-A2. サードパーティライセンス表記がない〔**済**〕

`build.ps1` は `--collect-all playwright` で
**Playwright（Apache-2.0）とその Node ドライバを丸ごと同梱**している。
Apache-2.0 は再配布時にライセンス本文と著作権表示の同梱を求める。

配布フォルダに `THIRD-PARTY-NOTICES.txt` を置くこと。

**現状の対応**: `build.ps1` が `pip-licenses` で依存のライセンス一覧を
`dist\edge-auto-capture\THIRD-PARTY-NOTICES.txt` に生成するところまで実装済み
（`pip-licenses` を用意できない環境では警告を出して配布自体は続行）。

### D-A3. 保存物のプライバシー注意書きがない（実務上いちばん効く）〔**未**〕

このツールは以下を保存する。

- **記録ON中に開いた全ページ**のフルスクリーンショットと全文テキスト
- `log.txt` に**訪問した URL を全部**
- 保存先は平文・アクセス制御なし

第三者が使えば、ログイン済みの業務システム、メール、人事情報、顧客の個人情報などが
**意図せず `output/` に溜まる**。しかも「記録中」バーは出るものの、
撮り忘れて放置すれば延々と溜まり続ける（`IMPROVEMENTS.md` B-3 のレート制限なしとも噛み合う）。

`USAGE.txt` に以下を明記した節を追加すること。

- 何が保存されるか（png / txt / _part.txt / log.txt の URL 履歴）
- 保存物の取り扱い責任は利用者にあること
- 不要になったら削除すること
- 撮影対象サイトの利用規約に触れる可能性があること

> 法的評価そのものは専門家の領域なので、ここでは
> **「注意書きを添える必要がある」という指摘に留める**。
> 条文の作成は法務に確認すること。

### D-B1. バージョンがどこにも出ない（**最優先の実装項目**）〔**済**〕

> **状態: 対応済み**（コミット `366a4a2`）。`__version__` を `infra.py:24` に一本化し、
> `pyproject.toml` は `dynamic = ["version"]` +

> `=== edge-auto-capture v{__version__} 起動 ===` を出す（`edge_auto_capture.py:457`）。

当時 `version = "0.1.0"` は `pyproject.toml` にあるだけで、
**exe にもログにも UI にも一切出ていなかった**。

結果、第三者から「動きません」と言われたときに
**「どの版をお使いですか」→「わかりません」** で詰む。配布物にとってこれは致命的だった。

| 単一の出所にする | `__version__` を 1 箇所（`infra.py`）に置き、pyproject / ログが参照する | ✅済 |

## C. 第三者環境で壊れる箇所

### D-C1. 書き込み不可の場所に置かれると、何も起きずに死ぬ（要修正）〔**済**〕

> **状態: 対応済み**（コミット `6510f3f`）。`infra.resolve_writable_dir`（`infra.py:49`）を追加し、
> `config.load_config` が `output_dir` 確定時に通す（`config.py:117-136`）。書き込み不可なら
> `%LOCALAPPDATA%\edge-auto-capture\` 等へ退避し、退避が起きたら `notify_fatal` で
> ログ＋ダイアログの両方に知らせる。どこにも書けなければ通知して終了。`main()` の
> `mkdir` も `try` で包み `notify_fatal`（`edge_auto_capture.py:367-371`）。以下は記録。

**実際に追える不具合だった。** `C:\Program Files\` など書き込み権限のない場所へ展開された場合:

1. `log()` は `except: pass`（当時 `infra.py:66`、現 `:91`）で**静かに失敗**
2. `set_log_dir` の `mkdir` も `except: pass`（当時 `infra.py:50`、現 `:76`）で**静かに失敗**
3. しかし `edge_auto_capture.py:321`（当時）の `config.output_dir.mkdir(...)` は
   **保護されておらず** `PermissionError` を送出していた
4. `--noconsole` ビルドなので stderr は誰にも見えない

→ **利用者から見ると「ダブルクリックしても何も起こらない」。ログもダイアログも残らない。**
`USAGE.txt` の「log.txt を確認してください」という案内も機能しなかった。

対処（実装済み）:

- `main()` の `mkdir` を `try` で包み、失敗時は `notify_fatal` でダイアログを出す
- 書き込み不可なら **`%LOCALAPPDATA%` へフォールバック**して動き続ける

### D-C2. ZIP から直接実行される〔**未**〕

Windows は ZIP の中身をダブルクリックで実行できてしまい、
その場合 `_internal\` が解決されず失敗する。

`USAGE.txt` に `_internal` を消すなという注意はあるが、
**「必ず展開してから実行」「Program Files など権限のない場所には置かない」**は書かれていない。
D-C1 とセットで追記すること。

### D-C3. config.ini を失うと起動不能〔**未**〕

削除・破損すると `notify_fatal` → `sys.exit(1)`（`config.py:87-91` / `:178-183`）。
ダイアログは出るので D-C1 よりましだが、配布物としては
**既定値で起動して config.ini を書き直す**自己修復のほうが親切。サポート負荷が下がる。

### D-C4. 多重起動〔**未**〕

`IMPROVEMENTS.md` A-5（プロファイル掃除の衝突）に加え、`output/` と `log.txt` の共有も起きる。
第三者は必ず二度押しする。単一インスタンス化（ミューテックス）か、少なくとも警告を出すこと。

## D. 導入障壁

### D-D1. 未署名 exe〔**署名受け口は済／証明書取得は保留**〕

`README.md` / `USAGE.txt` とも SmartScreen 警告に触れているが、
**企業環境では「警告」ではなく「ブロック」になる**ことがある
（AppLocker / WDAC / Intune のポリシー）。
「詳細情報 → 実行」で回避できない環境では、そもそも起動しない。

本格的に配る前提なら**コードサイニング証明書**が最も効く
（OV で警告軽減、EV なら SmartScreen の評価が即座に付く）。

> 年額のコストと発行手続きが要るため、これは技術判断ではなく**組織判断**。
> 配布規模が小さいなら、配布先の IT 部門に事前に許可リスト登録してもらう運用でも回せる。

**現状の対応**: `build.ps1` に署名ステップの受け口を用意済み。証明書を入手したら
`-CertPath`（PFX）または `-CertThumbprint`（証明書ストア／EV トークン）を渡すだけで
署名できる。指定が無ければ素通りし、未署名で配布される（挙動は従来どおり）。

#### 配布先 IT へ許可登録を依頼する連絡テンプレート

証明書を取得しない間、企業環境でブロックされる場合はこのテンプレートで許可登録を依頼する。
`< >` は配布ごとに埋める。SHA256 は `build.ps1` が出力する `*.zip.sha256` の値を使う。

```
件名: 業務ツール「edge-auto-capture」の実行許可のお願い

<IT 部門ご担当者> 様

業務調査で使用するツール「edge-auto-capture」を配布します。
現時点でコードサイニング署名が無いため、SmartScreen / AppLocker / WDAC / Intune の
ポリシーによってはブロックされる可能性があります。以下の実行ファイルの許可登録
（許可リストへの追加）をご検討いただけますでしょうか。

- ツール名 : edge-auto-capture
- 用途     : Web ページのスクリーンショット・テキストの自動保存（社内調査用）
- 配布物   : edge-auto-capture.zip（PyInstaller onedir 形式・未署名）
- 実行ファイル: edge-auto-capture.exe
- SHA256(zip): <build.ps1 が出力した SHA256 値>
- 依存      : Microsoft Edge / Google Chrome（同梱の Playwright ドライバ経由）
- 配布元    : <配布者名・連絡先>

ご不明点があればお知らせください。よろしくお願いいたします。
```

### D-D2. アンチウイルスの誤検知

PyInstaller 製バイナリはヒューリスティックで誤検知されやすい傾向がある。
`--onedir` を使っている（`--onefile` より誤検知しにくい）のは既に良い判断。

それでも出る場合は、署名するかベンダーへ誤検知報告するのが現実的な対処。
**配布前に主要な AV で一度確認しておく**こと。

### D-D3. 完全性の検証手段がない〔**済**〕

ZIP の **SHA256 を併記**すること。受け取り側が「正しいものを受け取ったか」を確認できる。

**現状の対応**: `build.ps1` が配布用 `edge-auto-capture.zip` を生成し、
`Get-FileHash` でその SHA256 を `edge-auto-capture.zip.sha256` に併記するところまで実装済み。

## E. 配布物そのもの

- **サイズが未計測** — `--collect-all playwright` は Node ドライバごと同梱するため、
  100MB を超える可能性がある。配布経路（メール添付は不可、等）に影響するので実測すること。
- **`output/` を配布フォルダに含めるか** — `README.md` の構成図には
  `output\` が「実行後に生成される」とあるが、空フォルダを同梱しておくと
  D-C1 の権限問題に早く気づける（展開時点で書き込み可否が分かる）。
